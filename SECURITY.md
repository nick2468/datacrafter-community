# Security

**Never report a security problem in an Issue, a Discussion or a pull request.** Those are
public, and a public report puts every DataCrafter user at risk until a fix ships.

## How to report

1. Open the **Security** tab of this repository.
2. Choose **Report a vulnerability**.
3. Describe the problem: the DataCrafter version, what an attacker can do, and the steps
   to show it.

GitHub private vulnerability reporting sends the report to the founder only. Nobody else
can see it.

## What happens next

The founder reads the report, replies in the same private thread and works on a fix. When
the fix ships, the release notes credit you, unless you ask not to be named.

## What to include, and what to leave out

- Include the version, the steps and the effect.
- Leave out real passwords, keys, tokens and real customer data. Use made-up values or the
  Demo instance.
